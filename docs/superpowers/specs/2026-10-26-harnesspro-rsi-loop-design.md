# HarnessPro 引导 Wan Block 研究的 RSI 执行方案

日期：2026-10-26。状态：设计完成，尚未实施或启动实验。

## 1. 目标与待验证主张

目标是让 Agent 根据研究轨迹，自主修改自己的 harness，并通过受控实验保留有效版本，使后续 Block 研究更有效或更省资源。

分别报告四种结果，不互相替代：

1. 工程完成：诊断、编辑、执行、选择、恢复能够闭环。
2. 过程收益：重复、无效调用或技术失败减少。
3. 任务收益：固定预算内得到质量更好的合法单权重候选，或更早达到相同任务质量。
4. RSI 证据：改动由 Agent 生成，经独立选择后用于下一代，并在新批次继续产生收益。需要至少两次连续版本更新；只有一次有效更新时报告一次自我改进，不能宣称持续递归收益。

工程完成或过程收益不单独支持任务收益；没有新颖压缩机制也可能改善研究效率，两类成果分开统计。复现 HarnessPro 的通用流程本身不作为新的学术贡献。拟研究的增量是：带昂贵 GPU 实验、资源失败和多层证据的科学研究任务中，harness 自我修改是否真实提高研究产出。

## 3. 最小架构

```text
运行当前 HarnessBundle，完成有界研究任务
  -> ResearchTrace（含请求、工具、实验、成本、失败和结果）
  -> Analyzer（问题、证据位置、替代解释、不确定性）
  -> Planner（省成本／平衡／重效果的修改计划）
  -> Editor（独立目录内产生实际补丁）
  -> 静态边界与执行检查
  -> 独立验证器运行父代及候选
  -> 固定初始性能下限 + Pareto 过滤/代表选择
  -> 下一代 HarnessBundle；失败保留、回滚、停止
```

这三个角色是调用协议，不要求并行子 Agent，也不要求不同基础模型。实现不依赖其他聊天的消息或权限。

初期修改能力限于三个组件：上下文/提示组织、训练证据检索、提案与实验选择策略。允许修改这些组件的代码或模板，不能只返回预设策略编号。正式比较前固定模型、解码参数和任务工具接口。

Editor 不可修改评测器、成功定义、数据划分、预算执行器、上层接受规则、远程权限和原始证据。检查器在候选目录之外运行；候选进程仅能访问训练证据及授权任务服务，验证/冻结集不可挂载。

## 4. 身份、数据和接口

### HarnessBundle

记录 `harness_id`、父代 ID、目录内容 SHA256、协议/工具接口/模型指纹、修改假设、补丁、来源和证据引用。ID 根据运行相关文件内容生成，排除日志、临时文件和运行状态；修改说明不参与行为身份。目录快照不可原地改写。

采用上游 `FilesystemHarnessStore` 的内容寻址思路，但不引入其整个 benchmark/runtime 依赖。元数据状态可以追加，源码身份不可覆盖。

### ResearchTrace

每个事件包含 task/run/epoch/harness/model 身份、输入输出或可寻址原件、单调计时、调用 token、工具/任务 ID、失败分类和证据级别。生成提案、修复、失败、重试、验证和元改进调用全部记账。

技术失败、资源受限、方法质量阴性、协议违规分别记录。缺失指标写 unavailable；不填零。使用真实服务 usage，不按字符数冒充 token。没有价格映射的本地 vLLM 只报 token 和时间，不编造美元成本。

### Diagnosis / PatchProposal

诊断必须引用原始轨迹文件及事件范围，说明观察、原因假设、替代解释和最小鉴别实验。计划包含修改组件、预期收益、回归风险和反证条件。编辑结果保存实际 diff；不得把人工写好的修复标为 Agent 发明。

初版使用完整可修改组件源码、精简训练诊断和相关历史，不默认复制全部长日志。原始轨迹支持定向读取；长输出保留可恢复原件。基线和候选具有相同的可访问证据范围。

## 6. 先解决表达能力这一混杂因素

现有 Block DSL 只能执行加权 MSE/cosine 和有限布局，仍是任务工具限制。初版不同时把 DSL 扩展算成 C 组自我改进。

执行前检查所有组能否通过同一已知策略的接口阳性对照。首批 RSI 比较限定在共同可表达任务上；若需要扩展初始化/训练日程接口，先独立实现、检查并冻结，再让 A/B/C 共享同一版本，重新预注册。旧研究中的人工策略只能作基线或阳性对照。

20 旧提案可用作训练诊断，不能作为 C 组新收益。源码不同、机制结构不同、行为不同、质量有效四项分开记录；不得以机制新颖率作为唯一任务目标。

## 7. 数据隔离与研究任务

研究任务是“一次受预算约束的提出—实验—分析过程”，视频 prompt 是其内部评测样本，两者分别标识。

M0 从历史故障建立检查样例：等价损失去重、运行槽/独立权重误判、资源 OOM 分类、保存重载、断点恢复。它们用于工程正确性，不作为方法收益。

研究轨迹另分 `meta-train`、`meta-validation`、`meta-test`：以完整任务实例及祖先轨迹分组切分，同源片段不得跨组；Agent 只读训练组。验证选择器只返回候选接受状态，不回传隐藏样本、原始日志或逐例评语。所有候选使用同一冻结检查标准。

Wan 的 T/D/V/F 划分继续独立存在。旧 D8 已参与历史分析，不能称新冻结集。旧 V8/F16 保持封存；新预检/开发数据只从合法训练/开发池构造。下一批正式验证/最终集在任何调用前由外置数据工具生成 manifest、内容散列并锁定。数据就绪门禁失败时停在预检，禁止拿公开的旧验证结果顶替。

任务清单和成功检查先生成一次、审阅并固定，然后才能开始 Agent 演化。合成检查可以验证协议、接口和已知错误，不能替代真实视频质量、效率或模型重载检查。

## 8. 分阶段执行

### M0：运行与证据基础

交付：冻结基线 bundle；统一任务服务和 trace；精确恢复、补丁边界、成本完整性检查。

必要验收：修改包外文件会被拒绝；失败与重试计费；恢复不重复成功任务；同一初始状态可重放；已知可表示任务的真实 worker 能更新并重载。已完成、指纹完全匹配的昂贵预检可以复用，不重训凑验收。

M0 未通过时不能启动演化。CPU/Fake 只证明工程功能。

### M1：历史证据上的闭环预演

用训练组历史轨迹触发 Agent 诊断和自主编辑。最多 2 个 epoch，每个 epoch 从一个当前父代产生 3 种方向的计划/候选，父代一同验证；最多 7 个不同 bundle。每个阶段最多一次技术性修复，所有修复计入预算；重复候选不补生成来凑数。

总上限：64 次真实模型请求、累计 200,000 输出 token；任一先到即停止。每次请求限制输入 32,000、输出 8,192 token；服务不支持实际 usage 或限制时必须明确降级/阻塞，不能冒称满足 token 协议。

验证必须重新执行候选的上下文/检索/决策逻辑，不能仅重放旧答案。独立执行检查器判断是否正确处理保留的输入案例；LLM 自述“修好了”不能通过。

通过条件：至少一个 Agent 自主生成的非等价补丁通过已知对照，并实际进入第二个 epoch 产生后代；记录所有选择和回滚。若未通过，在既定预算内修技术故障或报告能力未建立，不自动扩大 GPU 研究。

本阶段只检验闭环可用性和过程变化，不证明真实 Wan 收益。

### M2：真实 Wan 小试与正式对照

三组共享相同任务工具、模型和初始 harness：

| 组别 | 跨任务记忆 | harness 可修改 |
|---|---|---|
| A 固定 loop | 仅当前任务局部历史 | 否 |
| B 固定 loop + 记忆 | 合法训练历史 | 否 |
| C HarnessPro loop | 与 B 相同初始证据范围 | 是，含演化开销 |

B/C 初始检索器相同，C 的检索变化须来自其自主补丁。各组独立产物互不共享；重复组内使用相同初始状态、任务次序和配对种子，组间顺序轮换，动态租卡但不得中止其他作业。

先做 1 个配对运行，即 A/B/C 各一次。C 最多 2 个 epoch；Lite/Medium/Heavy 指修改目标，不是指定方案。所有候选验证、Analyzer/Planner/Editor 和修复成本均算入 C，不能把选赢家前的成本当免费。最多 7 个 bundle；在公共预算内做不完则少评候选，保留已完成父代。

首批采用明确的低成本改编：每个 epoch 只有一个当前父代，生成三种方向的补丁；根据训练侧固定检查的通过数排序、同分按内容 ID 排序，选择一个挑战者进入真实父子比较，其余只作未完成真实验证的档案。每个 epoch 最多一次训练侧轨迹采集和两次验证侧研究任务，两个 epoch 共最多 6 个 pilot。只有真实验证过的 bundle 才能进入任务级前沿。这个阶段验证递归修改闭环，不声称复现论文的完整三父代并行搜索；完整多分支需要本阶段有收益后另行设计预算。

每组每个独立运行的总上限：

- 20 次模型请求，累计输入 240,000、输出 40,000 实际 token；一次请求输入不超过 32,000、输出不超过 8,192。
- 最多 6 个新的 Wan 100 步 pilot；最多 1 个候选从 100 恢复至 500 步，故最多新增 1,000 次 optimizer 更新。A/B 可将相同额度用于各自研究；C 的训练侧采集、父子验证和失败后的重试也共享此额度。
- 任务 GPU 租用累计上限 6 小时，整组经过时间上限 12 小时；任一预算先耗尽就不再启动新阶段。训练进程在原子保存点结束，报告边界上的实际超支，不丢弃成本。
- 已生成且完全同指纹的 parent/teacher 数据可以缓存复用；缓存构建费用单列共享基础成本，不能只给某组免费优势。

Pilot 执行与质量评测须完整；单权重预算通过且开发 Semantic 相对同条件基线达到 +0.005，才允许条件续训。统一 100 步筛查只是本研究的预算边界，不能用它否定可能晚期生效的算法。执行失败、资源退出不能记成方法质量阴性。

固定质量评测保留 Semantic/Temporal/Motion 各项及视觉检查；方法最终晋升仍要求各项达到固定 dense 参照的 98%、延迟/显存各改善 5%、整体体积改善 10% 和单权重限制。开发的动态卡/warmup0 只能筛查，正式效率复核需固定设备、warmup1/repeat3。

只有完整小试中 C 相对 B 出现真实任务质量或达到相同质量的成本信号，才追加另外 2 个独立配对运行：固定研究目标下最佳合法候选 Semantic 绝对差达到 +0.005 且其他质量项不下降超过初始参照的 2%，或达到预设同一质量门槛的 GPU 租用成本至少下降 10%。若仅重复率改善，则报告过程收益，停止正式扩展。全部 3 个配对运行最坏训练预算 9,000 更新；这是上限，不是要求用满。若所有组 pilot 都无推进信号，不启动续训，不据此宣称 loop 无效。

## 9. 外层指标与选择

主指标是固定任务/预算下得到的最佳合法候选质量，以及达到预设相同质量的成本。严格达标率、新机制候选数、重复率、技术失败率是并列报告项。

单权重、有限数值和保存重载是合法性约束。合法但未达最终 98% 的候选可作为恢复进展指标；不能写成正式压缩成功。训练 MSE 不能替代视频指标。

外层每个 harness 的任务性能来自同一验证任务面板，前沿采用性能—任务 GPU 租用秒数；token 按输入/输出单列，并有共同上限。选择性能不低于初始 h0 的候选，再做 Pareto 过滤和三个偏好代表选择。相同表现和成本时优先父代，避免无证据漂移。没有足够真实验证证据时不作任务级晋升。

另外报告包括诊断、编辑和候选验证在内的总演化成本，以及冻结后 harness 单次执行成本。M1 预演消耗不计成部署成本，但必须出现在总研究账本。外层 GPU 成本是本研究的明确改编，不冒称与原论文 token 费用目标一致。

3 个独立运行只支持 pilot 重复性描述。正式扩样需要预注册效应量和功效/预算，不能因本轮结果不显著而无限补样。选择后的冻结集只用于确认一次，不用于补丁选择或继续改进。

## 10. 中断、失败与停止

状态机：`preflight -> collect -> diagnose -> plan -> edit -> check -> evaluate -> select -> next_epoch -> confirm -> complete`。状态、原始请求/响应、事件日志和源码快照原子保存。任务使用含输入/版本散列的幂等 ID。

- 技术故障：最多一次修复；执行器语义变化升级协议，不能当同条件续跑。
- OOM：保留实际峰值与失败证据；不得降尺寸后冒充原任务成功。
- 无候选、重复或均未通过：保留父代，达到 epoch 上限后结束。
- 预算耗尽：保存完整已完成结果；缺失任务不得作为通过，也不得只挑成功任务做平均。
- 门槛和隐藏验证资产不可被 Editor 修改；发现协议违规的候选无效，但其成本保留。

执行授权后使用一个协调器按门禁自动接续，不要求用户逐阶段重新启动。自动化只在关键新结果、明确阻塞和完成时通知；完整终止并归档后停用。

## 11. 实现里程碑和验收交付

1. M0：身份/轨迹/预算/任务服务。检查内容身份不变性、包外修改、失败计账、幂等与恢复，以及真实 worker 接口契约。
2. M1：诊断—编辑—执行—选择。检查证据引用、真实补丁生效、父代保留、第二代继承和不可见验证集；完成有界预演。
3. M2：三组协议与独立评测。检查同条件配对、元改进成本不遗漏、预算先到停止，以及不完整任务不被丢弃；通过预演才启动真实小试。
4. 结束审计：逐版本 diff 与来源、每组全部失败、API/token/GPU/更新数、原始质量结果、完整性、晋升/回滚、未决和研究主张范围。

实现应按里程碑给出独立可审阅提交，先做必要检查，再跑远端真实门禁；不把单元测试数量或源码变化量当作 RSI 效果。
