# Wan 四组 RSI 对照实验协议设计

## 目标

在重新占用 GPU 之前，先把 Fixed、Coding Agent、Agent + Memory 和完整 RSI 约束到同一套可审计的实验协议中。协议只负责启动前的一致性检查和运行清单，不改变历史实验结果，也不把配置验证当成实验成功。

## 固定的比较条件

- 四组使用同一 Wan 模型、同一 checkpoint、同一评价 manifest、同一 dtype 和同一随机种子集合。
- 每组使用相同的 `8 cases × 2 seeds = 16` 评价单元，并保留每个 case 的三次延迟测量。
- 默认比较三轮算法预算；四组使用互不相同的输出目录。
- Fixed 使用确定性的固定策略；Coding Agent 使用结构化代码生成但不读经验记忆；Agent + Memory 开启经验记忆但关闭自适应策略；完整 RSI 同时开启经验记忆和自适应策略。
- Coding Agent、Agent + Memory 和完整 RSI 使用相同的 provider/model/初始预算，避免把模型或预算差异误认为记忆或自适应策略收益。

## 运行清单

若尚未有四份配置，可从一份已固定 source revision 的真实 Wan 基线 YAML 生成四组
配置。生成器只改变四个控制臂的开关和独立输出目录，并把相对资产路径固定为绝对路径；
它拒绝 deterministic 基线作为 Coding Agent 输入，避免对照组名称与实际控制器不一致。

每个输出目录可写入 `run-manifest.json`。清单记录协议指纹、臂名称、配置摘要、checkpoint 和评价资产摘要、源代码 revision、预算以及实验控制变量。协议指纹只由可比较条件和四组控制变量组成，不包含本机路径，因此同一协议可在远程 GPU 主机复用。

小型评价文件使用内容哈希参与指纹；大型 checkpoint 和目录资产使用 snapshot/name
及可用性标识，绝对路径只保留在清单中。清单若记录资产未解析，后续对照统计必须拒绝
将其标记为可比实验。

若四组的协议指纹、臂名称、checkpoint、评价设置或预算不一致，对照脚本标记结果不可直接比较。缺失清单也会被明确报告，而不是静默地把四个旧目录拼成一个实验。

## 边界

协议预检不执行 Wan 推理、不启动 vLLM、不读取或重写旧模型决策，也不自动补齐缺失的远程资产。远程资产缺失时，应在实际 GPU 主机上运行同一预检命令；本机无 GPU 不构成重新执行完整实验的理由。
