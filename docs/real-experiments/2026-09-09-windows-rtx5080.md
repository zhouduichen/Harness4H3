## M4 real H3-derived child

On the same Windows host, the retained INT8 ConvRot H3 checkpoint was inspected as `M0000` (20,970,379,616 bytes, 50 blocks, complete H3 signature). `PrebuiltQuantizeOperator(bits=4)` selected the fixed NVFP4 deployment artifact and produced `M0001` (12,528,636,800 bytes, 50 blocks, complete H3 signature), a 40.27% model-size reduction. The parent file was not modified. Because the operator only adopts a trusted prebuilt variant, the child is explicitly marked `metrics_stale=true` until held-out quality and hardware measurements are attached.

## M5 controlled INT8 → NVFP4 acceptance

The first strict matrix held the following variables fixed: sanity prompt, seed `42`, 20 sampling steps, `352×640`, 22 frames, `simple` scheduler, CFG `5.0`, the same Q2 text encoder, video/audio VAE, Turbo LoRA, PathchSage node, and the same ComfyUI process. Before each model switch, `POST /free` was used with `unload_models=true` and `free_memory=true` so model-cache state was not a hidden variable. The benchmark stored this Operator Attribution:

```json
{
  "primary_intervention": "quantization",
  "secondary_changes": [],
  "controlled_variables": [
    "sampling_steps", "seed", "prompt", "scheduler", "resolution",
    "cfg", "vae", "text_encoder", "lora", "cache_reset_before_each_run"
  ]
}
```

| model | quality | wall time | peak VRAM | model size | semantic result |
| --- | ---: | ---: | ---: | ---: | --- |
| INT8 ConvRot parent (`M0000`) | 0.983151 | 205.34s | 15.783GB | 20.970GB | valid, 0% black |
| NVFP4 child (`M0001`) | 0.991137 | 89.48s | 16.358GB | 12.529GB | valid, 0% black |

The child quality delta is `-0.007986` (candidate slightly higher), model-size reduction is `40.26%`, and latency reduction is `56.42%`. The M5 hard gates are therefore: generation valid ✅, decode success ✅, black-frame rate `0` ✅, quality drop ≤`0.05` ✅, and efficiency improvement (size and latency) ✅. The runner records `accepted=true` for this M5 gate. The RTX 5080 TargetProfile separately reports `feasible=false` because the measured peak VRAM (`16.358GB`) is above its strict `16GB` limit; this is retained as a follow-up hardware constraint rather than hidden by the M5 quality/efficiency result.

The cache-reset diagnostic also explains the earlier black-frame observations: without a reset, INT8→NVFP4 switching reproduced all-black 8/6/4-step artifacts; after reset, NVFP4 20-step and 8-step artifacts were valid, while the 8-step score was only `0.834020`. Step reduction is consequently kept as a separate sensitivity branch, not combined with the accepted quantization child.

## M6 runtime-memory implementation and acceptance status — 2026-09-10

The M6 implementation is now present in the repository.
